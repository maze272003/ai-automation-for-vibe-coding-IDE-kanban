# Phase 5.2 — Code tab: explorer, editor and search (IDE-1, IDE-2, IDE-3)

Status: implemented and verified (2026-10-28)
Date: 2026-10-28
Parent spec: `docs/superpowers/specs/2026-10-18-autonomous-ai-ide-design.md` (§23, §25, §26)
Predecessor: `docs/superpowers/specs/2026-10-24-delete-project-and-git-view-design.md`

## 1. Context

Phase 5 covers the IDE experience. The Git tab (IDE-4 branch/commit history, shipped in
Phase 5.1) is the only screen so far. This sub-project delivers the read/write code surface for
the user's checkout:

| Story | Scope in this slice |
| --- | --- |
| IDE-1 | File explorer: lazy tree of the project's repository, one directory per request |
| IDE-2 | Monaco editor: open, edit and save text files in the user's checkout |
| IDE-3 | Search across files: literal text search implemented in Node, result list jumps to file/line |

The agent's worktrees stay invisible here. The Code tab always targets `projects.repoPath`, the
same checkout the Git tab mutates. Agent workspaces are read-only in the UI by design and are
not addressable through these endpoints.

## 2. Goals

- A project-level **Code** tab next to Board and Git, reachable at
  `#/projects/$projectId/code`.
- A keyboard-accessible explorer that lists the checkout one directory at a time, hides `.git`
  and never follows symlinks.
- A Monaco editor loaded lazily (no Monaco in the initial bundle), with syntax highlighting for
  the common text formats and explicit, optimistic saving.
- A literal search panel that reports `path:line:column` matches and opens the selected match.
- Server-side safety: all paths are repo-relative, contained in the repository after realpath,
  and denied while an agent run holds the project busy.
- Tests for path safety, caps, conflicts, routes and the UI helpers, plus e2e scenarios for
  browse/save/search, dirty guards, save conflicts and read-only binary/large files.

## 3. Non-goals

- No file-creation, rename, delete or drag-and-drop UI. Saving edits to an existing file is
  enough for IDE-2; a new-file flow can be a later slice. The write endpoint accepts a missing
  leaf when `expectedSha256` is null (used by tests and a future create flow), but the Code tab
  only opens and saves files that already exist in the explorer.
- No regex, whole-word or glob search (IDE-3 v1 is literal, case sensitivity toggle only).
- No integrated terminal (IDE-5), keyboard-shortcut map (IDE-6) or diagnostics viewer (IDE-7).
- No editing of agent worktrees, git objects, or files outside `projects.repoPath`.
- No binary editing, image preview or large-file editing.
- No multi-file tabs, split view or LSP completion/validation beyond Monaco's built-in tokenizer
  and the bundled language workers.

## 4. UX

### 4.1 Navigation

`TopBar` carries the same pill nav on Board, Code and Git:

```
Board | Code | Git
```

The active tab is a `<span aria-current="page">`; the other two are router `<Link>`s. The Code
page also carries the project key/name title and the `← Projects` link, mirroring `GitPage`.

### 4.2 Layout

```
┌ TopBar: project · Board | Code | Git · Search toggle ──────────────┐
├───────────────┬─────────────────────────────────┬─────────────────┤
│ Explorer      │ Editor                          │ Search          │
│ (240–288 px)  │ (min 0, flex-1)                 │ (320 px, toggle)│
│               │ path · dirty · Save · Reload    │ query · results │
└───────────────┴─────────────────────────────────┴─────────────────┘
```

- The explorer is always visible; the search panel is toggled from the toolbar (or `Ctrl+Shift+F`
  while the Code page has focus).
- With no file selected the editor area shows a short empty state ("Choose a file to edit").
- Search results replace the right column; selecting a result opens the file and reveals the
  matching line.

### 4.3 Explorer behaviour

- Root loads `GET /files/tree?path=`; directory rows load on first expand and cache their result.
- Each row is an `<li role="treeitem">` that owns its nested `<ul role="group">`; directories
  carry `aria-expanded`, the selected file carries `aria-selected`, and symlinks are
  `aria-disabled`. `Enter`/`Space` activates the focused row, `ArrowRight`/`ArrowLeft` expand and
  collapse a directory, and Tab moves through visible rows.
- Sort: directories first, then files, then symlinks; case-insensitive by name with a
  case-sensitive tie-break.
- `.git` and in-progress `.aik-*.tmp` files are never shown. Symlinks are shown with a distinct
  badge and are not expandable/opened.
- A directory with more than 1,000 children shows the first 1,000 and a "Showing the first N
  entries" note. Loading and error states are row-local; a failed directory can be retried.
- Row test ids use `encodeURIComponent(path)` (`file-row-src%2Fnote.txt`) so similar paths cannot
  collide.

### 4.4 Editor behaviour

- Selecting a text file loads `GET /files/content?path=…` and creates a Monaco model with the
  language inferred from the extension.
- The header shows the repo-relative path, an `Unsaved` badge when the buffer differs from the
  loaded text, and `Save`/`Reload` buttons. `Ctrl/Cmd+S` saves from anywhere on the Code page,
  including when focus is outside Monaco.
- `Save` is disabled when the buffer is unchanged, the file is binary, truncated, still loading,
  a save is in flight, or the conflict banner is open.
- Save sends `PUT /files/content` with the SHA-256 returned by the read. On `409 FILE_CHANGED`
  the page keeps the buffer, explains that the file changed on disk, disables `Save`, and offers
  `Reload`. A successful save refreshes the explorer's size for the saved path.
- Switching files, reloading with unsaved changes, or leaving the tab asks for confirmation; the
  in-app dialog is the guard. A save that finishes after the user switched files is ignored.
- Binary files show "Binary file — preview is not available" and no editor. Files larger than
  2 MiB return a decoded prefix (trimmed at a UTF-8 boundary) and show "This file is larger than
  2 MiB — showing a read-only preview" with Monaco read-only. UTF-16/32 BOM files are treated as
  non-editable binary so a UTF-8 save cannot silently corrupt them.
- Editor theme follows the app theme: `vs-dark` in dark mode, `vs` in light mode. Monaco's
  default token colors are accepted for v1.

### 4.5 Search behaviour

- Input is debounced by 250 ms and requires at least one non-whitespace character.
- A case-sensitivity toggle is persisted for the session (`sessionStorage`).
- Results show path, 1-based line/column and a trimmed preview; up to 500 matches. When the
  server caps the scan, the panel says "showing the first N matches"; when it hits a cap before
  any match, it says so and suggests narrowing the query.
- Case-insensitive matching folds each line with `toLowerCase` while retaining offsets back to
  the original text, so `path:line:column` remains correct for non-ASCII case mappings.
- Clicking a result opens the file and scrolls to the line, highlighting the match line.
- Empty result, loading and error states are explicit. `Escape` closes the panel.
- Result grouping and arrow-key navigation between results are follow-ups; v1 uses a flat list
  of buttons.

## 5. Contracts

New module `packages/contracts/src/files.ts`, re-exported from the package index.

```ts
export const MAX_FILE_BYTES = 2 * 1024 * 1024;   // read and write cap
export const MAX_TREE_ENTRIES = 1000;
export const MAX_SEARCH_RESULTS = 500;
export const MAX_SEARCH_FILES = 20_000;
export const MAX_SEARCH_FILE_BYTES = 1024 * 1024;
export const MAX_SEARCH_BYTES = 256 * 1024 * 1024;  // total bytes read by one search
export const MAX_SEARCH_ENTRIES = 50_000;           // dirs + files visited by one search

export const RepoRelPath = z.string().min(1).max(2000).superRefine(...);
export type RepoRelPath = z.infer<typeof RepoRelPath>;

export const FileTreeEntryDTO = z.object({
  name: z.string().min(1).max(500),
  path: RepoRelPath,
  type: z.enum(['file', 'dir', 'symlink']),
  size: z.number().int().nonnegative().nullable(),
});
export const FileTreeDTO = z.object({
  projectId: z.number().int(),
  path: z.string().max(2000),                    // '' for the repository root
  entries: z.array(FileTreeEntryDTO).max(MAX_TREE_ENTRIES),
  truncated: z.boolean(),
});

export const FileContentDTO = z.object({
  projectId: z.number().int(),
  path: RepoRelPath,
  content: z.string().max(MAX_FILE_BYTES).nullable(), // null binary; read-only prefix when truncated
  sha256: z.string().regex(/^[0-9a-f]{64}$/).nullable(),
  size: z.number().int().nonnegative(),
  binary: z.boolean(),
  truncated: z.boolean(),
  editable: z.boolean(),
});

export const FileWriteRequest = z.object({
  path: RepoRelPath,
  content: z.string().max(MAX_FILE_BYTES),           // plus NUL/lone-surrogate/UTF-8 byte checks
  expectedSha256: z.string().regex(/^[0-9a-f]{64}$/).nullable(),
}).strict();
export const FileWriteDTO = z.object({
  projectId: z.number().int(),
  path: RepoRelPath,
  sha256: z.string().regex(/^[0-9a-f]{64}$/),
  size: z.number().int().nonnegative(),
});

export const FileSearchMatchDTO = z.object({
  path: RepoRelPath,
  line: z.number().int().positive(),
  column: z.number().int().positive(),
  preview: z.string().max(400),
});
export const FileSearchDTO = z.object({
  projectId: z.number().int(),
  query: z.string().min(1).max(200),
  caseSensitive: z.boolean(),
  matches: z.array(FileSearchMatchDTO).max(MAX_SEARCH_RESULTS),
  truncated: z.boolean(),
  filesScanned: z.number().int().nonnegative(),
});
```

`RepoRelPath` rejects: empty, longer than 2,000 chars, absolute POSIX paths, Windows drive/UNC
forms, C0/C1 controls and bidi overrides (which can spoof how a path renders), `.`/`..`/empty
segments, segments named `.git` (case-insensitive), Windows-reserved characters `< > : " | ? *`,
trailing dots/spaces, and reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `CLOCK$`,
`CONIN$`, `CONOUT$`, `COM1–9`/`LPT1–9` including superscript ports). Both `/` and `\` are accepted
as separators; the service normalizes to `/` before use. The check is structural only; the service
also re-validates the resolved path, performs realpath containment, and refuses symlink
components. `FileTreeEntryDTO.name` must be a single segment without controls.

`FileContentDTO.content` is null for binary reads. Truncated text carries a read-only prefix (up
to 2 MiB, trimmed at a UTF-8 code-point boundary) so the user can inspect context; `sha256` is
null for both binary and truncated reads, and `editable` is `!binary && !truncated`. `size` is
the on-disk size, so a truncated response reports the full file size.
`FileWriteRequest.content` additionally rejects NUL, lone UTF-16 surrogates, and content whose
UTF-8 byte length exceeds `MAX_FILE_BYTES` (the JSON transport cap is larger, see §7).

`ERROR_CODES` gains `FILE_CHANGED` (HTTP 409) for optimistic-concurrency conflicts.

## 6. Server service

`apps/orchestrator/src/files/service.ts` — `WorkspaceFileService`.

Constructor deps: `projects: ProjectService`, `busy?: (projectId) => string | null`. It uses
`fs.promises` and the project's `repoPath`.

Every entry point:

1. Loads the project (`404 NOT_FOUND` for unknown ids).
2. Verifies `repoPath` exists and is a directory (`409 NOT_IN_WORKING_TREE` when missing).
3. Resolves real paths and asserts containment.

Path policy:

- Normalize `\` to `/`; re-validate the structural path.
- **Read/tree**: resolve the target with `realpath`; reject when the real path is not the repo
  root or under it (`400 VALIDATION_FAILED`), and reject when `realpath` differs from the expected
  path (a symlinked parent). The final component must not be a symlink. Missing target is
  `404 NOT_FOUND`.
- **Write**: resolve the *parent* directory with `realpath`; the final component must not be a
  symlink (checked with `lstat`); the target must not be a directory. Missing parent is
  `400 VALIDATION_FAILED`.
- `.git` (and case variants) is rejected for all operations even after normalization.
- Symlinks are listed as `symlink` in the tree and are never traversed or opened.
- Directory entries whose names cannot form a safe repo-relative path (controls, reserved names,
  trailing dots/spaces) are hidden rather than returned as invalid DTOs.

### 6.1 Tree

`tree(projectId, path = '')`

- `path` must resolve to a directory; a file path is `400 VALIDATION_FAILED`.
- Read one directory with `withFileTypes`; skip `.git` and in-progress `.aik-*.tmp` entries.
- Map `isDirectory()` → `dir`, `isSymbolicLink()` → `symlink`, else `file`.
- `size` only for regular files (`lstat().size`); null for dirs/symlinks. Stat only the rows that
  are returned, not every entry in a huge directory.
- Sort dirs first, then files, then symlinks; case-insensitive name with a case-sensitive tie-break.
- Cap at `MAX_TREE_ENTRIES`; `truncated` says whether more rows existed.
- `path` is echoed as the normalized repo-relative directory ('' for root).

### 6.2 Content

`read(projectId, path)`

- Must be a regular file (`400 VALIDATION_FAILED` for directories/symlinks).
- Open through the validated real path, `fstat`, and read at most `MAX_FILE_BYTES` bytes; never
  trust a pre-open size check alone.
- If the on-disk size is larger, return the decoded prefix with `truncated: true`,
  `sha256: null`, `editable: false`. The prefix is trimmed at a UTF-8 code-point boundary.
- Otherwise read the whole file. Binary detection: a NUL byte in the first 8 KiB, an unsupported
  UTF-16/32 BOM, or a strict UTF-8 decode failure. Binary files return `content: null`,
  `sha256: null`, `editable: false`.
- Text files return the UTF-8 content and the SHA-256 of the full bytes. A UTF-8 BOM is preserved
  so the editor round-trips the file without silently stripping it.

### 6.3 Search

`search(projectId, query, { caseSensitive = false, limit = MAX_SEARCH_RESULTS })`

- `query` is trimmed; empty after trim or longer than 200 chars is `400 VALIDATION_FAILED`
  (routes also validate).
- Walk depth-first from the root, deterministic order (dirs/files sorted case-insensitively).
  Every directory is re-resolved before descending so a junction swapped in mid-walk cannot leak
  outside the repository.
- Skip directories by name, case-insensitive: `.git`, `node_modules`, `dist`, `build`,
  `coverage`, `.next`, `.turbo`, `target`, `out`, `__pycache__`, `.venv`, `venv`, `.cache`,
  `vendor`, `.pnpm`, `.yarn`, `Pods`, `.svelte-kit`, `obj`.
- Never follow symlinks. Only regular files are read, through an `O_NOFOLLOW` handle where the
  platform supports it.
- Files larger than `MAX_SEARCH_FILE_BYTES` are skipped.
- Binary files are skipped (NUL, unsupported BOM, or invalid UTF-8).
- Literal substring match; case-insensitive mode lowercases both sides with an offset map.
- Each matching line yields one match at the first occurrence (line/column 1-based, preview
  trimmed/collapsed to 300 chars). Multiple matches on one line are not duplicated in v1.
- Stop at `limit` matches, `MAX_SEARCH_FILES` files, `MAX_SEARCH_ENTRIES` visited entries, or
  `MAX_SEARCH_BYTES` total bytes; `truncated` is true when stopped by a cap. `filesScanned`
  counts files opened/considered.
- Errors reading one file or directory (permissions, races) are skipped, not fatal.

### 6.4 Write

`write(projectId, body)`

- Serialize writes per project/path so the hash check and replacement are one critical section.
- Reject while `busy(projectId)` returns a reason: `409 PROJECT_BUSY` with that reason.
- Reject NUL content and content whose UTF-8 bytes exceed `MAX_FILE_BYTES`
  (`400 VALIDATION_FAILED`).
- Parent directory must exist; target must not be a directory or symlink.
- Existing file: compute its current SHA-256. If `expectedSha256 === null` or differs →
  `409 FILE_CHANGED` with a reload message.
- Missing file: only allowed when `expectedSha256 === null`; otherwise `409 FILE_CHANGED`.
- Write to a temp file in the same directory (`.aik-<uuid>.tmp`, mode 0600), `fsync`, then
  re-check the existing file's hash. Replace via `rename` for updates. For creates, use a
  hard-link or `COPYFILE_EXCL` so a concurrent create loses with `FILE_CHANGED` instead of being
  clobbered.
- Preserve the existing mode on POSIX, remove the temp file on every failure path, and return the
  new SHA-256 and byte size.
- Never create parent directories. Locked files surface as retryable `500 INTERNAL`.

## 7. Routes

`apps/orchestrator/src/api/routes/files.ts`

| Method | Path | Body/query | Response |
| --- | --- | --- | --- |
| GET | `/projects/:id/files/tree` | `path?` (string, may be empty) | `FileTreeDTO` |
| GET | `/projects/:id/files/content` | `path` | `FileContentDTO` |
| GET | `/projects/:id/files/search` | `q`, `caseSensitive?` (`true`/`false`), `limit?` | `FileSearchDTO` |
| PUT | `/projects/:id/files/content` | `FileWriteRequest` | `FileWriteDTO` (200) |

- Paths are query values; parse with `RepoRelPath` (tree allows `''`).
- `caseSensitive` is parsed from the literal strings `true`/`false`; anything else is
  `400 VALIDATION_FAILED`. A coerced boolean would turn `false` into `true`.
- `limit` is `z.coerce.number().int().min(1).max(MAX_SEARCH_RESULTS)`.
- `PUT` goes through `mutation()` (Idempotency-Key required) and returns 200. Its transport
  `bodyLimit` is `MAX_FILE_BYTES * 6 + 64 KiB` because JSON escaping can expand content; Fastify's
  413 (`FST_ERR_CTP_BODY_TOO_LARGE`) maps to `400 VALIDATION_FAILED` "Request body is too large".
  The service still enforces the real 2 MiB UTF-8 limit.
- `mutation()` serializes requests sharing an Idempotency-Key in-process, so two concurrent
  retries cannot both execute the write; a stored key with a different request hash returns
  `422 IDEMPOTENCY_MISMATCH`.
- Registered in `app.ts` and `test/helpers/app.ts` with `db`, `now`, `files`.

Monaco loading rules:

- The Code page itself is loaded with `lazyRouteComponent(() => import('./routes/code-page.tsx'))`,
  and `code-editor.tsx` dynamically imports `../lib/monaco.ts`; the initial bundle must not
  include Monaco (verified with `vite build` chunk output).
- Workers are imported with Vite's `?worker` suffix:
  `editor.worker`, `json.worker`, `css.worker`, `html.worker`, `ts.worker`.
- `self.MonacoEnvironment.getWorker(_, label)` returns the matching worker constructor.
- No CDN, no `@monaco-editor/react` (it defaults to jsDelivr).
- The CSP in `apps/desktop/src/main/ui-path.ts` already allows `worker-src 'self' blob:`.
- Models are disposed when the path changes/unmounts. The editor uses `automaticLayout`, and a
  `resetToken` reloads the buffer without remounting.

Save flow:

1. Load file → keep `{ content, sha256, editable }`.
2. Edit → `dirty = value !== content`.
3. Save → `PUT` with `expectedSha256: sha256`; on success set `content = value`, `sha256 = result.sha256`.
4. `FILE_CHANGED` → keep the buffer, show the conflict banner with `Reload`, and disable `Save`.
5. Save/open/project-switch races are guarded by request and save tokens; a late response never
   overwrites the newly selected file. Explorer expansion state survives a save refresh.

## 9. Errors and limits

| Situation | Status/code |
| --- | --- |
| Unknown project | 404 `NOT_FOUND` |
| Project folder missing | 409 `NOT_IN_WORKING_TREE` |
| Unsafe/escaping path, `.git`, directory read as file, binary write | 400 `VALIDATION_FAILED` |
| Missing file/dir | 404 `NOT_FOUND` |
| Write while project busy | 409 `PROJECT_BUSY` |
| Stale/missing `expectedSha256` | 409 `FILE_CHANGED` |
| Oversized content | 400 `VALIDATION_FAILED` |
| PUT body over the transport limit | 400 `VALIDATION_FAILED` (Fastify 413 mapped) |
| Search query empty/too long | 400 `VALIDATION_FAILED` |

All persisted/logged output continues to go through the existing redactor; these endpoints
return file content to the authenticated renderer only and never log it.

## 10. Security

- **Traversal**: structural validation + realpath containment + final-component symlink checks.
- **Symlink escape**: realpath on reads; `lstat` on writes; no traversal in tree/search.
- **Git internals**: `.git` segments rejected and hidden from the tree; search skips `.git`.
- **Resource exhaustion**: tree 1,000 rows; read/write 2 MiB; search 500 matches / 20k files /
  1 MiB per file / 256 MiB total / 50k visited entries; reads go through capped handles rather
  than whole-file reads.
- **Concurrency**: the existing `projectBusyReason` guard blocks writes during agent runs, so
  the app never races an agent's shell in the user's checkout. Writes and same-key retries are
  serialized, and create-only writes use an atomic exclusive operation.
- **XSS**: file content is rendered as text by Monaco, never as HTML. No `dangerouslySetInnerHTML`.
  The bridge URL validator allows the literal characters a search needs (`*`, `'`, `!`) but caps
  the encoded URL length.
- **Secrets**: no credentials are read or logged. `.env` files are visible to the user, which is
  intentional for an IDE; the renderer is the authenticated local user.
- **CSRF/origin**: unchanged API token + origin checks; the PUT still requires an Idempotency-Key.

## 13. Risks and follow-ups

- Monaco adds several MB to the lazy chunk (`editor.api-*.js` plus workers); acceptable because
  the Code route and Monaco are only fetched when the tab opens. A future slice can split language
  workers further.
- `npm audit` reports 8 advisories: 1 critical (`dompurify` through `monaco-editor@0.57.0`),
  1 high (Electron `44.9.0`), 5 moderate and 1 low. Suggested exact `dompurify@3.4.17` override and
  Electron `44.10.0` were not applied in this slice; upgrading is a separate dependency decision.
- Windows path aliasing (8.3 names, trailing dots) is mitigated but not exhaustively enumerated;
  containment uses realpath, resolved-path re-validation, and rejects the known forms.
- New-file/rename/delete UI, regex/glob search and editor preferences are deferred.
- Search result grouping and arrow-key navigation, cache invalidation when files change on disk,
  dev-CSP coverage for workers, static-font MIME/cache headers, the idempotency
  execute-then-persist crash window, absolute paths in internal error logs, allocation for very
  large `readdir` results, locale-dependent sort, and broader e2e failure-path coverage are
  recorded follow-ups.
- Large repositories still pay a directory walk per search; the 20k-file / 50k-entry /
  256 MiB caps bound it, but the server walk is not cancellable and a future version should
  stream/cancel searches.

# Office Agent Activity — Click-to-Watch + Live Tool Bubbles — Design

Date: 2026-11-04
Status: approved (user) · pending implementation
Amends: `2026-11-04-pixel-agents-office-design.md` (§ Security review: office preload; § Non-goals: tool-level fidelity)

## Problem

The office shows every agent run as a pixel character, but the characters carry no
real activity (one generic `aik-<role>` bubble per run) and clicking one does
nothing. The user wants to click a character and watch that agent's OpenCode
session — the coding (tool calls) and the thinking (reasoning) — live.

## Goal

1. **Click a character → open the existing "Terminal Logs & Thoughts" modal** for
   that character's story, live-streaming the run's OpenCode reasoning/tool/text
   parts (the modal and its 2 s polling endpoint already exist).
2. **Live tool bubbles**: while a run is in flight, the character's bubble shows
   the agent's actual tool activity (`Reading foo.ts`, `Editing bar.ts`,
   `Running: npm test`) and a `Using Thinking` status between tool calls.

## Non-goals (phase 2+)

- Push/SSE upgrade of the Terminal modal (keeps its working 2 s poll).
- Persisting full transcripts (no new tables; `agent_runs.log_path` stays unused).
- Fixing the modal's dead "Open in CLI" button (pre-existing bug, separate cycle).
- Any upstream change to pixel-agents (still pinned 1.5.0, spawn-only).
- A new in-office detail panel (the existing modal is the detail view).

## Verified integration facts

**Pixel-agents 1.5.0** (clone at `%LOCALAPPDATA%\Temp\opencode\pixel-agents`, all
read in their source):

- Clicking a hooks-only external agent selects it and shows its one-line overlay
  label; no drawer/panel/terminal exists for it, and `focusAgent` is a no-op on
  their standalone server. The **only externally observable click signal** is the
  `focusAgent` JSON frame the webview sends over its WebSocket
  (`webview-ui/src/App.tsx:337-357`).
- The webview learns `id → directoryName` from the `agentCreated` /
  `existingAgents` broadcasts (`server/src/httpServer.ts:222-235`,
  `clientMessageHandler.ts:592-618`); `agentClosed` removes an id.
- Bubble/status text comes from `PreToolUse`/`PostToolUse` hooks via
  `formatToolStatus` (`providers/hook/claude/claude.ts:27-73`): `Read/Edit/Write`
  render `Reading/Editing/Writing <basename(file_path)>`, `Bash` renders
  `Running: <command>`, unknown tools render `Using <toolName>`. `PostToolUse`
  ignores `tool_name`. Statuses update live for hooks-only agents
  (`agentToolStart` broadcasts; proven by their `--no-terminal` e2e).
- No click-through/link/postMessage exists for embedders; wrapping the page's
  `WebSocket` from a preload that runs before page scripts is the only seam.

**Our app**:

- `runOneShot` polls `GET /api/session/{id}/message` every 400 ms already
  (`apps/orchestrator/src/agents/runtime.ts:263-296`); raw parts contain
  `{type:'tool', id, name, state:{status, input}}` and reasoning parts
  (shape proven by `spikes/spk-1/out/probe-A-messages.json`).
- All three agents persist `opencode_session_id` into `agent_runs` live via the
  existing `onSessionCreated` callback (planner.ts:189-206, implementer.ts:169-183,
  reviewer.ts:257-271) — the click target's session is always known.
- `GET /stories/:id/agent-run` returns `{run, messages}` while in flight
  (stories/service.ts:548-626); the Terminal modal renders reasoning/tool/text
  parts with filters (`apps/ui/src/components/kanban/terminal-modal.tsx`).
- The outbox → `/events` SSE → `EventForwarder` → `aik:event` pipeline exists;
  `EVENT_TOPICS` already reserves `run.output` (unused, different meaning — final
  output text) so a **new** `run.activity` topic is added instead.
- Story keys embed the project key (`<PROJ>-<n>`), unique in practice across
  projects; the office character label is exactly `${storyKey} ${role}` and is
  generated by us (`office/bridge.ts:73`).

## Architecture

```
┌─ click path ────────────────────────────────────────────────────┐
│ office WebContentsView (their SPA)                              │
│   office-preload.cjs: wraps WebSocket, observes focusAgent      │
│   + agentCreated/existingAgents → id→label map                  │
│   → ipc 'aik:office-agent-click' (label string only)            │
│ desktop main: exact webContents-id sender check → window        │
│ renderer: parse label → GET /stories/key/:key → navigate to     │
│   board with ?terminal=<storyId> → Board opens TerminalModal    │
└─────────────────────────────────────────────────────────────────┘
┌─ bubble path ───────────────────────────────────────────────────┐
│ runOneShot 400 ms loop: diff message parts → onActivity([...])  │
│ agents: appendRunActivity() → outbox topic 'run.activity'       │
│   (one row per poll tick; summaries redacted + truncated)       │
│ PixelAgentsBridge: run.activity → PreToolUse/PostToolUse posts  │
│   on session aik-run-<runId> → live bubble text                 │
└─────────────────────────────────────────────────────────────────┘
```

## Component design

### 1. Office preload (`apps/desktop/src/main/office-preload.ts` → `dist/office-preload.cjs`)

Bundled by `build.mjs` like `preload.cjs` (esbuild, cjs, external electron).
webPreferences of the office view gain `preload: path.join(__dirname,
'office-preload.cjs')` (sandbox + contextIsolation stay on).

The preload replaces `window.WebSocket` with a pass-through subclass that:

- on `send`, parses JSON; a `focusAgent` frame resolves the character id against
  the maintained `id → directoryName` map (learned from `agentCreated` /
  `existingAgents` broadcasts; entries dropped on `agentClosed`) and
  `ipcRenderer.send('aik:office-agent-click', label)` — the label string only.
- never mutates, holds, or replays frames; failure of any parse step is silent
  (the page must not break).

**Security posture change (amendment to the 2026-11-04 office spec):** the office
view now runs a preload. Containment: sandboxed (no node), contextIsolation,
single outgoing IPC channel, string-only payload, runs in their origin (never
sees `app://` pages). The receiving `ipcMain.on` handler accepts frames **only**
from the office view's exact `webContents.id` (`event.sender.id` compared to the
manager's view, not a URL heuristic), then relays to our renderer window.

### 2. Click wiring (desktop main → renderer → modal)

- `OfficeViewManager` gains `onAgentClick(handler)` registration;
  `registerOfficeIpc` adds the guarded `aik:office-agent-click` listener;
  `index.ts` forwards to `win.webContents.send('aik:office-agent-click', label)`.
- Contracts: `AikWindowApi.office` gains `onAgentClick(cb: (label: string) => void)`
  (+ unsubscribe); preload implements it with `ipcRenderer.on`.
- UI: the `/office` route subscribes; `parseOfficeLabel(label)` (new pure helper
  in `apps/ui/src/lib/office.ts`: role = substring after the **last** space,
  storyKey = the rest) feeds `GET /stories/key/:key`.
- **New route** `GET /stories/key/:key` → `StoryService.getByKey(key)` (join
  project for the DTO; 404 when unknown).
- The office route then navigates to the story's board with a one-shot search
  param `?terminal=<storyId>`; `Board` consumes it on mount, opens
  `TerminalModal` in terminal mode for that story, and clears the param. Board's
  existing local modal state is untouched.

### 3. Activity capture (runtime + agents)

- `RunOneShotInput` gains optional `onActivity?: (events: RunActivityEvent[]) =>
  void`; `RunActivityEvent = { kind: 'tool-start' | 'tool-end'; name: string;
  summary?: string }`. Inside the existing 400 ms loop, diff the fetched messages
  against seen part ids:
  - tool part appears (status running/pending) → `tool-start` with `name` =
    the OpenCode tool name and `summary` from its input (basename of `input.path`
    for file tools; `input.command` for bash; truncated to 120 chars).
  - tool part reaches completed/failed → `tool-end`.
  - reasoning part appears since the last tick → one `tool-start` with
    `name: 'Thinking'` (bubble shows `Using Thinking`); any following text/tool
    part emits its `tool-end`.
  - No callback or no new parts → no events. The loop's terminal-idle logic is
    unchanged.
- Name mapping lives in the bridge (§4), not the runtime — the runtime stays
  OpenCode-shaped.
- Agents (planner/implementer/reviewer) pass `onActivity` once the run row exists;
  each tick's events are appended as **one** outbox row via a new
  `appendRunActivity(db, now, runId, events, redact)` helper in
  `agents/run-events.ts`: topic `run.activity`, `storyId`, provenance `system`,
  data `{ runId, role, storyKey, projectKey, events: [...] }`; every `summary`
  passes the orchestrator redactor before persisting (rows also feed the UI SSE).
  `redact` is injected into the three agents from `app.ts` (optional dep,
  identity default). Hard cap: 300 activity rows per run (drop silently after,
  one warn log).

### 4. Bridge translation (`run.activity` → hooks)

`hookEventsForRunActivity(data)` maps each event of a row to the same
`aik-run-<runId>` session:

| Event | POST | Bubble effect |
|---|---|---|
| `tool-start` name ∈ read/edit/write | `PreToolUse {tool_name: 'Read'|'Edit'|'Write', tool_input: {file_path: summary}}` | `Reading/Editing/Writing <summary>` |
| `tool-start` name = bash | `PreToolUse {tool_name: 'Bash', tool_input: {command: summary}}` | `Running: <summary>` |
| `tool-start` name = grep/glob | `PreToolUse {tool_name: 'Grep'|'Glob', tool_input: {}}` | `Searching …` |
| `tool-start` other/Thinking | `PreToolUse {tool_name: <Capitalized>, tool_input: {}}` | `Using <Name>` |
| `tool-end` | `PostToolUse` | clears the tool bubble |

`drain()`'s topic filter adds `run.activity`; health/queue/retry/redaction
semantics are exactly the existing ones. Unknown `data.events` shapes are skipped
(defensive parse like `toRunEventData`).

## Error handling & edge cases

- Office not running / bridge offline: activity rows pile up in the bounded queue
  like today (cap 100, oldest dropped) — worst case stale bubbles, self-heals.
- Click before the label map is populated (broadcast race): the preload drops the
  click silently; clicking again works once `agentCreated` arrived.
- Run finished between click and modal open: the modal already renders the last
  run's session messages (`lastRun`) — graceful.
- Implementer/reviewer sessions run in worktrees; summaries may carry worktree
  paths — harmless (display only, redacted, local).
- Rapid tool churn: events are batched per 400 ms tick into one row; cap 300
  rows/run bounds DB growth (~2 min of continuous activity at worst).
- Feature off (`agentOffice: false`): no preload click path (view never loads),
  no bridge; `run.activity` rows are still appended (they also serve the UI SSE)
  — this is accepted and cheap.

## Security review

- The office preload is the single deviation from the reviewed office spec and is
  containment-first: sandboxed, contextIsolated, no node, one string channel,
  exact-webContents sender check in main. It observes only the pixel-agents page's
  own WebSocket traffic on 127.0.0.1.
- `summary` values are redacted (orchestrator redactor) and truncated before any
  persistence or IPC; tokens/secrets already covered by the redactor's secret
  list can therefore not leak into bubbles, outbox rows, or logs.
- No new outbound network access; no upstream code changes; the office view
  remains tokenless/read-only server-side.

## Testing

- **UI**: `parseOfficeLabel` unit tests (story keys with digits/hyphens, roles);
  office route subscribes/unsubscribes; `?terminal=` consumed once by Board.
- **Desktop**: office-view click forwarding is not unit-testable without
  Electron (existing gap) — the preload is kept dumb-thin; the sender check is a
  pure id comparison reviewed by test where extractable.
- **Orchestrator**: runtime diffing against fixture message arrays (spk-1 probe
  shapes); `appendRunActivity` outbox rows (batching, redaction, cap) per agent;
  bridge translation table incl. defensive skips (extend
  `apps/orchestrator/test/office-bridge.test.ts`); `GET /stories/key/:key` route
  test.
- **Live proof**: extend the manual end-to-end office script — post a
  `run.activity` sequence, assert `agentToolStart` broadcasts arrive; manual
  click-through check recorded as a verification gap (needs the embedded view).

## Definition of done

- `npm run check:pins && npm run lint && npm run typecheck && npm test` pass.
- With the office on: a story run's character bubble cycles through real tool
  statuses and `Using Thinking`; clicking a character opens the Terminal modal
  showing that story's live reasoning/tools/output.
- No secret appears in bubbles, outbox rows, logs, or the renderer (redacted).
- Spec amendment + README office section updated.

# Phase 5.3 — Integrated Terminal (IDE-5) Design

Date: 2026-11-05
Status: approved (user pre-approved self-adjudication for this phase; reviewed by a three-agent panel — BA, security, feasibility — all findings adjudicated into this revision; see Execution record in the plan)
Parent spec: `docs/superpowers/specs/2026-10-18-autonomous-ai-ide-design.md` §26.1 (IDE-5), §26.2 (IDE-1…IDE-7 common criteria), §5.1 (transport choices), §5.2 (layering), §21 (security)
Position: Phase 5 (IDE experience). IDE-1/2/3 shipped in Phase 5.2, IDE-4 in Phase 5.1. This spec delivers IDE-5.

## Problem

The app has a real code surface now (Code tab, Git tab), but no way to run a shell
inside the app. The only "terminal" surfaces are the read-only agent log modal
(`terminal-modal.tsx`) and an external OS window (`aik:open-terminal-cli` spawns a
detached `cmd.exe`). Users need an integrated terminal to inspect repos, run ad-hoc
commands and try things without leaving the app.

## Goal

IDE-5, per the parent spec: an integrated terminal in the renderer, running a real
Windows pseudo-console (ConPTY) at the user's full rights, clearly labelled as such,
with the working directory chosen by the user, ending when the window closes, and
unreachable by agents.

## Verified integration facts (checked 2026-11-05; kill-behavior facts added by the security review)

**Dependencies (registry)**

- `@xterm/xterm@6.0.0` — MIT — the spec's "xterm.js 6" pin, now the scoped package.
- `@xterm/addon-fit@0.11.0` — MIT — resize-to-container addon (same-commit release family as xterm 6).
- `node-pty@1.1.0` — MIT — latest stable (beta 1.2.0-beta.18 is NOT eligible; repo pins exact stable releases only). Tarball ships `prebuilds/win32-x64/{pty.node,conpty.node,conpty_console_list.node}` **plus** `conpty/conpty.dll`, `conpty/OpenConsole.exe`, winpty fallbacks, and ~30 MB of `.pdb` files. Both win32 bindings are N-API (`src/win/{conpty,winpty}.cc` use `node_api.h`).

**node-pty probe (this machine, 2026-11-05, temp dir `Temp\opencode\pty-probe`)**

- Installed with `-E node-pty@1.1.0` with npm install-scripts **blocked** (npm 12 gating): the module still loads — 1.1.0's loader resolves `prebuilds/<platform>` directly (`lib/utils.js loadNativeModule`), so its install/postinstall scripts are unnecessary.
- `spawn('cmd.exe', …)` under Node 24.17: ConPTY session ran, `echo probe-ok-42` output captured, `exit` → exit code 0 (`EXIT 0` / `SAW-ECHO true`).
- N-API ⇒ ABI-stable across Node 24 and Electron 44; the same prebuild loads in main. Final in-app proof is the e2e test.

**node-pty kill semantics (source-verified by the security review — this is why T-9 exists)**

- Default ConPTY path (`useConptyDll=false`): `kill()` synchronously calls only the native `ClosePseudoconsole` — **no `TerminateProcess`**. The per-PID kills of the console's process list are performed by a `child_process.fork('conpty_console_list_agent')` with a **5-second timeout**, asynchronously.
- With the repo's `runAsNode: false` fuse (`scripts/apply-fuses.ts`, enforced by `scripts/verify-packaging.ts`), that `fork` in the **packaged app** boots the full Electron app instead of a Node agent (single-instance lock kills it), the agent never answers, and kill degrades to the 5 s fallback that terminates only the direct shell PID.
- Conclusion: relying on `pty.kill()` alone would break the "session ends when the window closes" invariant in the packaged app. The design therefore belt-and-braces every kill with a synchronous `taskkill /PID <pid> /T /F` (T-9).

**Our architecture (facts that shape the design)**

- The renderer never sees the API token or port; every orchestrator call goes `ipcRenderer.invoke('aik:request')` → main → `fetch` with the Bearer token (`apps/desktop/src/main/bridge.ts:35` — "plan deviation 1", a deliberate, reviewed deviation from the parent spec's original token-in-preload idea).
- `BridgeRequest` (`bridge-request.ts`) deliberately **excludes `/events`** from renderer-initiated paths; push data reaches the renderer only as forwarded `aik:event` / `aik:system` / `aik:office-agent-click` IPC events.
- The CSP served for `app://ui` is `connect-src 'self'` (`ui-path.ts`) — a renderer `ws://127.0.0.1:*` connection would be **blocked** without weakening the CSP.
- There is **no WebSocket server anywhere** in desktop or orchestrator today; no `ws` dependency. The office bridge is a WS *client* to the pixel-agents server.
- Precedents in main: `aik:open-terminal-cli` (`bridge.ts:175`) spawns a detached `cmd.exe`; `OfficeViewManager` (`office-view.ts`) is the manager-with-`destroy()` precedent, destroyed on `win.on('closed')` (`index.ts:159`); `registerOfficeIpc` (`office-view.ts:114`) is the **silent-return** untrusted-guard precedent (it does NOT throw), vs `bridge.ts assertTrusted` which does throw. `apps/desktop/test/office-view.test.ts` refuses to import modules that pull in `electron` — electron-touching registration must be thin and untested at unit level.
- UI: React **StrictMode is enabled** (`main.tsx`), so effect-driven opens double-mount in dev; the panel design must be StrictMode-safe. Dark/light theme = `dark` class on `<html>` (a `MutationObserver` re-themes Monaco in `code-page.tsx`); theme tokens live in `index.css` (`--background`, `--foreground`, …). Pure logic lives in `src/lib/*.ts` with vitest tests; components carry `data-testid` for Playwright.
- Packaging: `build.mjs` bundles `main.cjs` with only `electron` external; e2e and `npm start` run the **unpacked** `apps/desktop/dist` where externals resolve from hoisted `node_modules`. electron-builder's smartUnpack is theory-only in this repo (no script invokes electron-builder; `package:verify` checks NSIS flags + fuses only). `npm run check:pins` enforces exact versions.

## Decision log

| # | Decision | Choice and rationale |
|---|---|---|
| T-1 | Terminal transport | **Guarded IPC (`aik:terminal-*`) with the PTY in the desktop main process**, not the parent spec's "WebSocket from the renderer with the launch token". Rationale: (a) exposing the launch token to the renderer would undo the repo's established invariant ("the token never leaves the main process", bridge.ts:35); (b) `connect-src 'self'` blocks `ws://` from the `app://ui` document; (c) a WS server would need a second Host/Origin/token enforcement surface; IPC already has sender validation + zod on every channel. Recorded as **plan deviation 2** (parent §26.2 and §5.1 amended below). Everything the parent spec requires of the terminal is preserved: user-only, user's rights, labelled, user-chosen cwd, dies with the window. |
| T-2 | PTY host | Desktop **main process** (not the orchestrator). The terminal is a UI facility, not a story-execution concern; main already spawns processes and owns window lifetime; keeps the orchestrator bundle free of native-module changes. |
| T-3 | PTY backend | `node-pty@1.1.0` (exact). N-API win32-x64 prebuild proven on this machine; ConPTY is the only practical pseudo-console API on Windows. The pty factory is injected (`createPty`) so unit tests never spawn processes. Default ConPTY mode (`useConptyDll` untouched). |
| T-4 | Frontend | `@xterm/xterm@6.0.0` + `@xterm/addon-fit@0.11.0` (exact). Pure-JS renderer deps bundled by Vite; DOM renderer (no webgl addon) so e2e can assert rendered text. |
| T-5 | Placement & scope | A **bottom panel on the Code tab** (`/projects/:id/code`), toggled by a toolbar button and `Ctrl+`\`. v1 = **one session at a time** per panel (open/close); tabs are deferred. cwd defaults to `project.repoPath`; a "Change directory" control reuses `window.api.pickDirectory`. Joe, confidence Medium: the parent names no placement; the Code tab is where a terminal belongs today; a global dock would collide with the office overlay and modal flows. |
| T-6 | Honesty | The panel carries a permanent notice: **"Runs with your Windows user rights"** (parent §26.2 "clearly labelled"). No containment (no Job Object, no env scrubbing) — by design, it is the *user's* shell. |
| T-7 | Agent isolation | "No agent can reach these capabilities": the terminal manager lives in desktop main, reachable **only** through `aik:terminal-*` IPC with sender validation; the orchestrator has no route to it, OpenCode sessions/permissions are untouched, and the office `WebContentsView` has **no preload** so office content has no `ipcRenderer`. |
| T-8 | Output pacing | The manager coalesces pty output per session and flushes on an injected scheduler (default `setImmediate`). Keeps IPC message count sane under flood; trivially testable; no timers. node-pty itself delays exit delivery ~1 s (`FLUSH_DATA_INTERVAL`), so the panel must tolerate data/exit arriving out of band — it does (events are id-keyed). |
| T-9 | Kill semantics (review finding) | Every kill = `pty.kill()` **plus** synchronous `taskkill /PID <pid> /T /F` on win32 (errors swallowed; double-kill is safe), via an injectable `killTree(pid)` so tests never spawn taskkill. Reason: node-pty's own tree-kill is async, 5 s-timeout, and broken under the packaged app's `runAsNode:false` fuse (see Verified facts). Non-win32: `pty.kill()` only. **Honesty:** this kills the console-attached tree; processes the user *deliberately detached* (`start notepad`, GUI apps, daemons) survive — by design, it is the user's shell. |
| T-10 | Owner lifetime (review finding) | Sessions record their owner `webContents`. The manager subscribes to each owner's `did-start-navigation`, `render-process-gone` and `destroyed` events and kills that owner's sessions — closing the leak where a **hard reload** (which does not run React cleanup) or renderer crash would otherwise leave live, invisible shells until the 8-session cap fills. SPA navigations (TanStack pushState) do fire `did-start-navigation`, but arrive with `isSameDocument: true` and are ignored; only real document navigations (hard reloads, links — `isSameDocument: false`, with a details-less emit treated the same, leak-safe) kill the owner's sessions. The owner is consumed as an `EventEmitter`-shaped object, keeping the manager electron-import-free and unit-testable. |
| T-11 | Schema single-sourcing (review finding) | The terminal IPC payload **zod schemas and bound constants live in `packages/contracts/src/terminal.ts`** (precedent: `files.ts` DTO schemas in contracts), so desktop ipc and the UI's `clampGrid`/chunker share one source of truth instead of triplicating bounds. |
| T-12 | Untrusted-sender behavior (review finding) | Terminal channels follow `registerOfficeIpc`'s **silent-return** pattern, not throwing `assertTrusted`: an untrusted sender gets `{ok:false, reason:'BAD_REQUEST'}` / `false` and nothing is executed. Handlers never throw: all pty calls are wrapped (`resize`/`write` on an exited-but-undeleted session throw inside node-pty; caught → `false`). |
| T-13 | StrictMode-safe open (review finding) | The panel's open effect is guard-token'd; if the invoke resolves after unmount, the session is closed fire-and-forget (`close(id)`), never merely ignored — otherwise every dev-mode remount leaks a live shell. |
| T-14 | Explicit asarUnpack (review finding) | `apps/desktop/package.json` `build.asarUnpack: ["**/node-pty/**"]` — do not rely on smartUnpack theory. `.pdb` filtering (~30 MB) is a deferred optimization. `apps/desktop/test/packaging-config.test.ts` asserts the unpack entry. |

## IPC contract (single-sourced in `packages/contracts/src/terminal.ts`)

Exported bounds and schemas:

```ts
export const TERMINAL_MAX_SESSIONS = 8;
export const TERMINAL_MAX_WRITE_BYTES = 65_536;   // per write call
export const TERMINAL_CHUNK_BYTES = 16 * 1024;    // panel-side paste chunking
export const TERMINAL_COLS = { min: 2, max: 500 } as const;
export const TERMINAL_ROWS = { min: 2, max: 300 } as const;
export const TERMINAL_MAX_CWD = 4096;

export const TerminalOpenPayload = z.object({
  cwd: z.string().min(1).max(TERMINAL_MAX_CWD).optional(),
  cols: z.number().int().min(TERMINAL_COLS.min).max(TERMINAL_COLS.max),
  rows: z.number().int().min(TERMINAL_ROWS.min).max(TERMINAL_ROWS.max),
});
export const TerminalWritePayload = z.object({ id: z.number().int().min(0), data: z.string().min(1).max(TERMINAL_MAX_WRITE_BYTES) });
export const TerminalResizePayload = z.object({ id: z.number().int().min(0), cols: …, rows: … });
export const TerminalClosePayload = z.object({ id: z.number().int().min(0) });
```

Result/event types (in `bridge.ts`):

```ts
export type TerminalOpenResult =
  | { ok: true; id: number; cwd: string }
  | { ok: false; reason: 'BAD_REQUEST' | 'TOO_MANY_SESSIONS' | 'INVALID_CWD' | 'SPAWN_FAILED'; message?: string };
export interface TerminalDataEvent { id: number; data: string }
export interface TerminalExitEvent { id: number; exitCode: number }
export interface TerminalOpenOptions { cwd?: string; cols: number; rows: number }
```

`AikWindowApi` gains:

```ts
terminal: {
  open(options: TerminalOpenOptions): Promise<TerminalOpenResult>;
  write(id: number, data: string): Promise<boolean>;      // false = unknown id / invalid / exited
  resize(id: number, cols: number, rows: number): Promise<boolean>;
  close(id: number): Promise<boolean>;
  onData(listener: (e: TerminalDataEvent) => void): () => void;   // ipc 'aik:terminal-data'
  onExit(listener: (e: TerminalExitEvent) => void): () => void;   // ipc 'aik:terminal-exit'
};
```

| Channel | Dir | Payload | Result |
|---|---|---|---|
| `aik:terminal-open` | invoke | `TerminalOpenPayload` | `TerminalOpenResult`; zod fail → `{ok:false, reason:'BAD_REQUEST'}` |
| `aik:terminal-write` | invoke | `TerminalWritePayload` | `boolean`; invalid/unknown → `false` |
| `aik:terminal-resize` | invoke | `TerminalResizePayload` | `boolean` |
| `aik:terminal-close` | invoke | `TerminalClosePayload` | `boolean` |
| `aik:terminal-data` | main→renderer | `TerminalDataEvent` (data unbounded string — shell output) | — |
| `aik:terminal-exit` | main→renderer | `TerminalExitEvent` | — |

Untrusted sender → same error shapes, nothing executed, no throw. `message` on
`SPAWN_FAILED` carries the spawn error text (never a secret — it is a process error).

## Component design

### 1. `packages/contracts/src/terminal.ts` — schemas + bounds (T-11)

As above; re-exported from `@aik/contracts`. Unit-tested in
`packages/contracts/test/terminal.test.ts` (accept/reject matrix for each payload:
missing/oversized/mistyped fields, bound edges).

### 2. `apps/desktop/src/main/terminal.ts` — `TerminalManager`

Electron-import-free (only `node:child_process`, `node:fs`, `node:os`, `node-pty`).

- Deps (all injectable): `{ createPty?, schedule?, killTree?, send }`. Defaults:
  `createPty` = node-pty `spawn` (top-level import; the module is `external` in the
  bundle and loads fine in vitest — probe-verified), `schedule` = `setImmediate`,
  `killTree(pid)` = `spawnSync('taskkill', ['/PID', String(pid), '/T', '/F'])` on
  win32 with errors swallowed (no-op elsewhere), `send(channel, payload)` = main's
  isDestroyed-guarded `sendToWindow`.
- `open(payload, owner)`: `owner` is `{ id: number; on(event, cb): unknown }` — the
  real `event.sender` webContents satisfies this; tests pass a fake `EventEmitter`.
  Validates cwd (`fs.promises.stat` → existing directory; absent → `os.homedir()`),
  enforces the 8-session cap, spawns `%COMSPEC%` (fallback `cmd.exe`) with
  `{ name: 'xterm-256color', cols, rows, cwd, env: process.env }`, stores
  `{ pty, ownerId, cwd, pid, buffer: '' }`, subscribes the owner-lifetime hooks
  (T-10) once per owner, returns `{ ok: true, id, cwd }`. Spawn throw →
  `{ ok: false, reason: 'SPAWN_FAILED', message }`. Session ids: monotonic from 1.
- Output coalescing (T-8): `onData` appends to the session buffer; `schedule(flush)`
  drains via `send('aik:terminal-data', { id, data })`. Order preserved per session.
- `onExit` → flush pending → `send('aik:terminal-exit', { id, exitCode })` → delete.
- `write/resize/close(id, …)` → route with try/catch (T-12); `false` on unknown id
  or throw. `close` = `pty.kill()` + `killTree(pid)` + delete (idempotent; the
  delayed node-pty exit event for a deleted session is a no-op).
- `killAll()` — synchronous, idempotent; `kill()` each session; no sends (window is
  going away). Also drops owner subscriptions.
- Never logs. No pino in desktop main; terminal bytes are never persisted.

### 3. `apps/desktop/src/main/terminal-ipc.ts` — `registerTerminalIpc`

Mirrors `registerOfficeIpc` (thin, electron-importing, e2e-covered — not unit-tested
per the office-view precedent). Deps `{ manager, isTrustedSender }`. Each handler:
sender check → **silent** error shape on untrusted → `safeParse` with the contracts
schemas → route to manager, passing `event.sender` as the owner on `open`. In e2e
mode, index.ts exposes `manager` on the existing `__aik` seam.

`index.ts` wiring (next to OfficeViewManager):

```ts
const terminalManager = new TerminalManager({ send: sendToWindow });
registerTerminalIpc({ manager: terminalManager, isTrustedSender });
win.on('closed', () => terminalManager.killAll());
// inside the existing before-quit handler, before supervisor.stop():
terminalManager.killAll();
```

(`killAll` twice on the window-close path is fine — it is idempotent.)

### 4. Contracts `bridge.ts` + preload

`AikWindowApi.terminal` as above; preload adds the member (`invoke` for commands;
`ipcRenderer.on/off` subscriptions returning unsubscribe functions — copy the
`office.onAgentClick` shape). Contracts+preload land in one commit (the preload
implements the whole interface or typecheck fails).

### 5. `apps/ui/src/lib/terminal.ts` — pure helpers (unit-tested)

- `xtermTheme(dark: boolean)` — plain object from the real Aurora tokens
  (`--background`, `--foreground`, accent, cursor) — light/dark variants.
- `clampGrid(cols, rows)` — clamps to `TERMINAL_COLS/ROWS` (imports the contracts consts).
- `chunkInput(data: string): string[]` — splits a large paste into
  `TERMINAL_CHUNK_BYTES` slices on code-point boundaries (surrogate-pair safe).
- `terminalNotice(error, exitCode)` — status-line copy ("Session ended (exit code
  N)" / spawn-failure reasons).

### 6. `apps/ui/src/components/code/terminal-panel.tsx` — `TerminalPanel`

- Props: `{ defaultCwd: string; onClose: () => void }`. At most one session.
- Open effect (StrictMode-safe, T-13): guard token; `terminal.open({ cwd, cols,
  rows })`; on resolve-after-unmount → fire-and-forget `close(id)`. On success:
  `new Terminal({ theme: xtermTheme(dark), … })`, FitAddon, `term.open(div)`,
  `fit()` → `resize` with clamped grid.
- Wiring: `term.onData(d => for (const c of chunkInput(d)) terminal.write(id, c))`;
  `terminal.onData(e => e.id === id && term.write(e.data))`;
  `terminal.onExit(e => e.id === id && setExitCode(e.exitCode))` (tolerates the ~1 s
  node-pty exit delay).
- `ResizeObserver` → `fit()` → `resize(id, clampGrid(...))`. Theme follow via the
  code-page `MutationObserver` pattern → `term.options.theme`.
- Keyboard accessible: the xterm container is a tab stop (`tabindex=0`), the panel
  is a labelled `region` (`aria-label="Terminal"`), the terminal is **focused on
  open** so the user can type immediately.
- Exited state (`data-testid="code-terminal-exited"`): notice + **Restart**
  (`code-terminal-restart`) re-opens with the same cwd. Failed open: error line with
  the reason, no xterm.
- Header: cwd (middle-truncated), "Change directory" (`code-terminal-cwd` —
  pickDirectory → close + reopen), close button; permanent badge
  "Runs with your Windows user rights" (`code-terminal-notice`).
- Unmount / close: `terminal.close(id)` fire-and-forget + `term.dispose()`.

`code-page.tsx`: `terminalOpen` state; toolbar button

## Session lifecycle matrix

| Event | Action |
|---|---|
| User opens panel / Restart / change directory | `open` → new id, xterm attached, terminal focused |
| User types / pastes | `write(id, chunk)` per chunk (paste chunked ≤16 KiB) |
| Shell produces output | coalesced → `aik:terminal-data` → `term.write` |
| Shell exits (any cause) | `aik:terminal-exit` (may lag ~1 s) → ended state + Restart; session deleted |
| User closes panel / leaves Code tab (unmount, incl. dev remount) | `close(id)` + `term.dispose()`; pty.kill + killTree |
| Panel resized | `fit()` → `resize(id, clampGrid(...))`; throws swallowed → `false` |
| **Hard reload / renderer crash** | owner lifetime hook kills that owner's sessions (T-10) |
| Window closed / app quits | `killAll()` — synchronous `pty.kill()` + `taskkill /T /F` per session; idempotent |
| Owner webContents destroyed with sessions live | owner hook cleans up; further sends dropped by the isDestroyed guard |

**Out of scope by design (T-9 honesty):** processes the user deliberately detaches
from the shell (`start notepad`, GUI apps, background daemons) survive app exit —
this is the user's own shell, not a sandbox.

## Security review

- **Thesis**: the user's shell at the user's rights, on purpose (parent §26.2). Not
  a sandbox feature; never claimed to be.
- **Who can reach it**: only the trusted-sender renderer (silent-guard on all four
  channels). Agents (OpenCode sessions), orchestrator jobs, the office bridge and
  check runners have no path to these channels or to `TerminalManager`; the office
  view has no preload at all.
- **Escalation assessment (review)**: a compromised renderer already holds
  `aik:request` (full orchestrator API + Bearer) and `aik:open-terminal-cli`
  (detached interactive shell in any cwd); the terminal adds no material escalation
  under the app's threat model (renderer runs only CSP-restricted app code).
- **Input surface**: every payload validated by the contracts schemas with hard
  caps (write ≤ 64 KiB, cols 2..500, rows 2..300, cwd ≤ 4096, ≤ 8 sessions).
  Handlers never throw; all pty calls wrapped.
- **No secrets**: terminal bytes cross IPC only; never logged or persisted (no pino
  in desktop main, no crashReporter in the repo); the redactor guards *persisted*
  output and none is persisted. Launch/gateway tokens remain main-process-only.
- **Orphan control**: T-9 kill belt-and-braces; T-10 reload/crash hooks; killAll on
  both teardown paths; `close` deletes before the delayed exit event arrives.
- **Adjacent pre-existing flaw (recorded, out of scope)**: `aik:open-terminal-cli`
  builds its detached-shell command with `shell:true` and an unbounded `sessionId`
  (`bridge.ts:177–198`) — a renderer-side injection vector pre-dating this phase.
  Filed to the backlog for a follow-up cycle; this spec does not touch it.
- **DoS note**: a flooding `cat huge.bin` grows the coalesce buffer transiently;
  bounded by per-tick drain and by being the user's own command. Byte-rate cap is a
  non-goal.

## Non-goals (deferred)

- Terminal tabs / split panes / multi-session UI (the cap-8 headroom is defensive).
- Terminal on pages other than Code; global dock.
- Agent worktree terminals (agent output stays in the Terminal Logs modal).

## Acceptance criteria

1. On the Code tab, the user can open a terminal panel that spawns a real ConPTY
   shell at a user-chosen cwd (default: the project root), type commands, and see
   output; the terminal is keyboard-focusable and focused on open (toggle via
   button or `Ctrl+`\`).
2. The panel is labelled "Runs with your Windows user rights" at all times.
3. Window close / app quit kills every shell session and its console-attached
   process tree synchronously (user-detached processes are out of scope by design).
4. Leaving the Code tab / closing the panel / hard-reloading the page ends the
   session; reopening starts a fresh one. A shell that exits on its own shows an
   ended state with a Restart control.
5. No agent-side surface can open, write to or read from the terminal (no
   orchestrator route, no OpenCode permission, no office path — verified by review).
6. All terminal IPC is sender-guarded, schema-validated and capped; handlers never
   throw; pastes larger than 64 KiB are chunked, never dropped.
7. `npm run check:pins && npm run lint && npm run typecheck && npm test` pass; e2e
   proves the live path (type → output → exit → restart; navigation closes the
   session) in the real Electron app, and asserts the shell process is gone after
   close.

## Test strategy

- **Unit (contracts)**: `packages/contracts/test/terminal.test.ts` — payload
  accept/reject matrices incl. bound edges.
- **Unit (desktop)**: `apps/desktop/test/terminal.test.ts` — manager with fake
  `createPty`, fake `send`, fake `schedule`, fake `killTree`, fake owner
  `EventEmitter`; temp-dir cwd validation (paths asserted under OS temp per repo
  rule): open/ids/cap/cwd validation + reason mapping; write/resize/close routing,
  unknown id, throwing pty (exit race); coalescing order + flush-on-exit; exit
  cleanup; killAll idempotency + killTree called with the session pid; owner
  lifetime hooks (reload/crash/destroyed kill only that owner's sessions).
  `registerTerminalIpc` itself is thin and e2e-covered (office-view precedent).
- **Unit (UI)**: `apps/ui/test/terminal.test.ts` — theme dark/light values (real
  token values), clampGrid bounds, chunkInput (sizes, surrogate pairs), notice copy.
- **E2E**: `e2e/tests/terminal-panel.spec.ts` —
  (a) open Code tab → toggle panel → click `.xterm` → type `echo aik-terminal-<fixed>`
  → expect the text rendered → `exit` → ended state (tolerant timeout for the ~1 s
  exit lag) → Restart → prompt returns;
  (b) navigate to Git tab and back → session was closed (fresh session opens);
  via the `__aik.terminalManager` seam, read the session pid and assert with
  `tasklist` polling that the shell process is gone after leaving the tab.
- **Full gate** before completion (repo rule), plus `npm run e2e`.

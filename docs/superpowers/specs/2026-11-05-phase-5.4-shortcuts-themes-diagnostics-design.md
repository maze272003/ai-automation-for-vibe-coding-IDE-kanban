# Phase 5.4 — Keyboard Shortcuts, Themes and Advanced Diagnostics (IDE-6, IDE-7) Design

Date: 2026-11-05
Status: approved (user pre-approved self-adjudication; independent BA, security, feasibility and UX/accessibility reviews completed; findings adjudicated into this revision — see the Execution record in the plan)
Parent spec: `docs/superpowers/specs/2026-10-18-autonomous-ai-ide-design.md` §23 (UI screens 20–21), §26.1 (IDE-6/IDE-7), §26.2 (IDE-1…IDE-7 common criteria), §17.3 (`/health`, `/diagnostics/export`), §21 (diagnostics and logs)
Position: Phase 5 (IDE experience). IDE-1/2/3 shipped in Phase 5.2, IDE-4 in Phase 5.1, IDE-5 in Phase 5.3. This spec delivers the remaining Phase 5 stories, IDE-6 and IDE-7.

## Problem

The app is keyboard-hostile outside the Code tab: navigation, theme switching and the
shortcut surface are undiscoverable, and only the Code tab implements a handful of
hard-coded `window` key listeners. The theme can be toggled but cannot follow the OS,
and the existing dialog surface is hard-coded dark, so light-theme dialogs fail contrast.

On the operations side, REL-7 shipped retention pruning and a redacted diagnostics
*export* endpoint, but there is no UI for it and no way to inspect the logs, recent
errors, component health or backups that the REL-7 work creates. The parent spec's
screen 21 (component health, recent errors, log viewer, DB backup/restore, diagnostics
export) is therefore only half-present.

## Goal

- **IDE-6:** a single keyboard-shortcut registry with global navigation/help/theme
  bindings and a discoverable, accessible shortcut reference; theme preference
  Light / Dark / System with live OS-theme following.
- **IDE-7:** an advanced Diagnostics page with component health (database, logs,
  backups, OpenCode, gateway, GitHub, Ollama), recent errors, a redacted read-only log
  viewer, on-demand database backup with backup listing, and a native "Export
  diagnostics…" flow that saves the existing redacted archive.

## Non-goals

- User-rebindable shortcuts. IDE-6 is an S story; a registry + reference + global
  bindings deliver the value. Rebinding (capture UI, conflict detection, reset) is
  recorded as a later enhancement.
- New log storage, a new errors table, or live log streaming. The viewer tails the
  existing rotating files on demand.
- Restoring a live database. Existing restore remains available only from the
  startup-failure screen when the database cannot open (data-loss safety); this is a
  recorded parent-spec amendment below.
- Runtime retention editing; the existing `/maintenance/prune` endpoint is unchanged.

## Verified facts (checked 2026-11-05)

**Keyboard/theme**
- `apps/ui/src/lib/theme.ts` stores `aik.theme` as `light|dark` and applies `.dark` on
  `<html>`; `main.tsx` applies it before React renders; `SettingsPage` owns a local
  `useState` copy and a toggle button.
- Dark/light tokens are the `:root` and `.dark` blocks in `index.css`. Monaco and xterm
  already re-theme from a `MutationObserver` on the `<html>` class, so resolving
  `system` into the same class needs no component changes there.
- Three ad-hoc global listeners exist today: `routes/code-page.tsx` (Ctrl+S,
  Ctrl+backtick, Ctrl+Shift+F, Escape), `components/git/scm-panel.tsx`
  (Ctrl+Enter commit) and `components/kanban/terminal-modal.tsx` (Escape). The Code tab
  ones move to the registry; the other two stay component-local but are **listed** in
  the reference as local shortcuts.
- There is no Electron application menu override, so Ctrl+1/2/3, Ctrl+`,`, Ctrl+Shift+D,
  Ctrl+Shift+L and F1 are free; Ctrl+R / Ctrl+W / Ctrl+Shift+I stay reserved by
  Electron and must not be bound.
- React StrictMode is enabled. Global listeners must use one stable effect with a
  handler ref (the `lib/events.ts` pattern) so remounts cannot double-fire.
- Radix Dialog sets `role="dialog"` but **not** `aria-modal` (verified in the installed
  package); global navigation must therefore guard on `[role="dialog"]`.
- `dialog.tsx` hard-codes `bg-[rgb(16_20_36/0.92)]`; with light-theme `--foreground`
  `#15161a` that is a dark-on-dark contrast failure. The same pattern exists in the
  toast. Both are tokenized in this phase.

**Diagnostics**
- `apps/orchestrator/src/maintenance/diagnostics.ts` already builds a redacted archive
  from the DB, projects, providers and `logsDir/*.log`; `app.ts` constructs it with
  `logsDir: paths.logs`, `version` and the shared redactor (which has the launch token,
  gateway token and office token registered as secrets).
- `apps/orchestrator/src/maintenance/retention.ts` prunes jobs/outbox/idempotency rows,
  removed worktrees and old log files; REL-7 tests cover it.
- The log writer is `RotatingFile`: current file plus `.1`…`.5`; `orchestrator-stdio.log`
  is written by the desktop main process (append-only, no rotation). Both are JSON-lines
  (pino) or raw stdio.
- `openDatabase` uses `VACUUM INTO` for startup backups and prunes to 5
  (`packages/db/src/backup.ts`); there is no on-demand backup endpoint.
- `restoreLatestBackup` in `apps/desktop/src/main/bridge.ts` is guarded to a
  `fatal`/`database_corrupt` supervisor state; it is not a general-purpose restore.
- The renderer's bridge (`aik:request`) deliberately excludes `/events` by a literal
  string check that URL normalization can bypass (`/x/../events`), and it currently
  forwards `/diagnostics/export`. Both are closed in this phase so the archive really is
  main-only.
- The renderer bridge path regex allows dots, query strings and percent-encoding; the
  CSP is `connect-src 'self'`. New capabilities must go through guarded IPC or the
  existing bridge path.
- `/health` today exposes only `components: {db}` although the parent §17.3 lists
  db/opencode/gateway/github/ollama. IDE-7 closes that gap on the richer diagnostics
  health route without changing the existing `/health` response.

## Decision log

| # | Decision | Choice and rationale |
|---|---|---|
| K-1 | Theme model | A stored **preference** (`light` / `dark` / `system`) resolves to a **resolved theme** (`light` / `dark`) and keeps the existing `aik.theme` key and the `.dark` class contract. `system` follows `matchMedia('(prefers-color-scheme: dark)')`. Legacy values keep working; default stays `dark` so existing behaviour and e2e appearance specs do not change underneath the user. |
| K-2 | Theme state | One module-level store (`lib/theme.ts`) with `useSyncExternalStore` (`lib/use-theme.ts`). It owns the media-query listener and the `<html>` class, and caches one immutable snapshot so React never sees a fresh object per read. No new context provider, no cross-process settings write; localStorage remains the established renderer preference store. |
| K-3 | Shortcut registry | A pure `lib/shortcuts.ts` holds every binding as `{id, chord, label, scope, group}`. `mod` means Ctrl on Windows/Linux and Meta on macOS. `scope: 'global'` bindings are dispatched by one `useGlobalShortcuts` hook; `scope: 'code'` bindings stay page-owned but are matched and displayed from the same registry; `scope: 'local'` rows (Git commit, dialog Escape) are display-only. This removes the hard-coded chords without a risky app-wide command bus. |
| K-4 | Shortcut safety | Global bindings are ignored when the event target is editable (`input`/`textarea`/`select`/contenteditable, which includes Monaco's textarea) and when **any** `[role="dialog"]` is open. There is no exception: F1 must not steal Monaco's command palette or the terminal's F1. Help remains reachable from the sidebar/Settings buttons. `event.preventDefault()` fires only after a binding matches and a handler exists. Reserved Electron chords are not bound. |
| K-5 | Discoverability | A `ShortcutsDialog` lists all bindings grouped by Navigation / View / Editor / Help / Local, with scope notes, and is opened by F1 (outside editors), a sidebar "Keyboard shortcuts" button, and a Settings appearance button. A small `lib/shortcut-help.ts` custom event lets any route ask RootLayout to open the dialog without prop drilling. |
| K-6 | Diagnostics read API | Read routes live on the existing authenticated orchestrator API: `GET /diagnostics/logs`, `GET /diagnostics/logs/:file?tailBytes=`, `GET /diagnostics/errors?limit=`, `GET /diagnostics/health`, `GET /diagnostics/backups`. They are read-only, bounded and redact through the same `Redactor` as the export. `/health` is left unchanged for compatibility. |
| K-7 | Log containment | A log name must match a strict allow-list regex (`^[A-Za-z0-9][A-Za-z0-9._-]*\.log(?:\.\d+)?$`) **and** exist in `readdir(logsDir)`. Entries are `lstat`-checked and symlinks are rejected; the target is `realpath`-checked under `realpath(logsDir)`; after opening, `fstat` re-confirms a regular file. Tail reads are bounded (4 KiB–256 KiB, default 64 KiB) and drop a leading partial line. Path traversal, alternate data streams, absolute paths and non-`.log` files are unreachable. |
| K-8 | Error extraction | "Recent errors" are parsed from the tail of pino JSON-lines logs (`level >= 40`: warn/error/fatal), sorted newest-first, capped at 200. Non-JSON stdio lines are skipped. Every returned message/detail has already passed through the redactor and a fail-closed secret scan; hits are omitted. No raw log line crosses the API boundary. No schema migration is needed. |
| K-9 | Backup | `POST /diagnostics/backup` runs `VACUUM INTO` into `backups/` with the existing timestamped name scheme, prunes to 5, and is single-flight + throttled (10 s) so a compromised renderer cannot loop full-DB copies. It returns `{ok, name, size}` or a fixed reason. Listing is read-only. **Restore stays startup-failure-only**; the page shows the restore note. |
| K-10 | Export transport | "Export diagnostics…" is a main-process capability (`aik:diagnostics-export`): main fetches `/diagnostics/export` with the launch token, shows a native Save dialog, and writes the pretty-printed redacted archive. The renderer never receives the archive or chooses a path. The bridge path allow-list denies `/diagnostics/export`, and the IPC handler checks the sender without throwing and returns a union. |
| K-11 | UI placement | A dedicated `/diagnostics` route linked from the sidebar (Operations), matching parent screen 21. Settings keeps theme/model/office/about; diagnostics is not buried in Settings and is keyboard-reachable (`Ctrl+Shift+D`). |
| K-12 | Contracts | Bound constants plus request schemas live in `packages/contracts/src/diagnostics.ts`; response DTOs are plain interfaces. The desktop IPC result types and the UI import the same names. Existing `/diagnostics/export` archive shape stays backward compatible, with additive DB statistics. |
| K-13 | Health components | `/diagnostics/health` reports `db`, `logs`, `backups` from real checks, plus `opencode`, `gateway`, `github`, `ollama` from cheap non-mutating probes supplied by `app.ts` (configured/connected state, not a network probe that could hang). Each component has `{status:'ok'|'degraded'|'unavailable', detail}`. This closes the parent §17.3 component list without making the health request slow or side-effecting. |
| K-14 | Honesty/security wording | The log viewer states "Redacted for known secrets; treat logs as sensitive." The backup card says "Keeps the 5 most recent backups; older backups are deleted." The export helper says the archive is redacted but still sensitive. Restore is explained as startup-failure-only. The diagnostics page is user-only: none of these capabilities touch OpenCode permissions or agent access. |
| K-15 | Overlay tokens | Add `--overlay-fill` (light: near-white, dark: deep navy) and use it for `Dialog` and toast surfaces so light-theme overlays meet AA. Also darken light `--muted-2` to `#5f6472` (≥4.5:1) for small metadata text. |

## Architecture

```
Renderer (app://ui)
  RootLayout
    useGlobalShortcuts (F1 / Ctrl+1..3 / Ctrl+, / Ctrl+Shift+D / Ctrl+Shift+L)
    ShortcutsDialog (opened by F1, sidebar/Settings buttons via shortcut-help event)
  SettingsPage -> useTheme() -> lib/theme.ts (localStorage + matchMedia + .dark)
  CodePage    -> matchesShortcut() for save/search/terminal
  DiagnosticsPage -> api.get /diagnostics/{health,logs,errors,backups} -> guarded bridge -> main -> fetch + token
                  -> window.api.exportDiagnostics() -> native save dialog (main)
Orchestrator
  registerMaintenanceRoutes
    DiagnosticsService: listLogs / readLog / recentErrors / health / listBackups / createBackup / exportArchive
    Redactor (launch + gateway + office tokens, secret patterns)
  logsDir: <data>/logs/*.log[.N]   backupsDir: <data>/backups/*.db
Desktop main
  aik:diagnostics-export -> fetch /diagnostics/export -> dialog.showSaveDialog -> write JSON
  aik:request             -> normalized path allow-list (denies /events, /diagnostics/export)
```

## API contract (single-sourced in `packages/contracts/src/diagnostics.ts`)

```ts
export const DIAGNOSTICS_LOG_TAIL = { min: 4_096, max: 262_144, default: 65_536 } as const;
export const DIAGNOSTICS_ERROR_LIMIT = { min: 1, max: 200, default: 50 } as const;
export const DIAGNOSTICS_MAX_BACKUPS = 5;
export const DIAGNOSTICS_BACKUP_THROTTLE_MS = 10_000;
export const DIAGNOSTICS_RESTORE_NOTE =
  'Restore is offered from the startup failure screen when the database cannot open. Restoring a live database is intentionally blocked.';

export const DiagnosticsLogName = z.string().min(1).max(160)
  .regex(/^[A-Za-z0-9][A-Za-z0-9._-]*\.log(?:\.\d+)?$/);
export const DiagnosticsLogParams = z.object({ file: DiagnosticsLogName });
export const DiagnosticsLogQuery = z.object({
  tailBytes: z.coerce.number().int().min(DIAGNOSTICS_LOG_TAIL.min)
    .max(DIAGNOSTICS_LOG_TAIL.max).default(DIAGNOSTICS_LOG_TAIL.default),
});
export const DiagnosticsErrorsQuery = z.object({
  limit: z.coerce.number().int().min(DIAGNOSTICS_ERROR_LIMIT.min)
    .max(DIAGNOSTICS_ERROR_LIMIT.max).default(DIAGNOSTICS_ERROR_LIMIT.default),
});

export interface DiagnosticsComponentHealth {
  status: 'ok' | 'degraded' | 'unavailable';
  detail: string;
}
export interface DiagnosticsLogFileDTO { name: string; size: number; modifiedAt: string }
export interface DiagnosticsLogListDTO { files: DiagnosticsLogFileDTO[] }
export interface DiagnosticsLogContentDTO extends DiagnosticsLogFileDTO {
  content: string; truncated: boolean; redacted: true;
}
export type DiagnosticsErrorLevel = 'warn' | 'error' | 'fatal';
export interface DiagnosticsErrorDTO {
  file: string; time: string | null; level: DiagnosticsErrorLevel;
  message: string; detail: string | null;
}
export interface DiagnosticsErrorsDTO { errors: DiagnosticsErrorDTO[]; scannedFiles: number }
export interface DiagnosticsHealthDTO {
  status: 'ok' | 'degraded';
  uptimeSeconds: number;
  versions: { app: string; node: string; electron: string | null };
  memory: { rssBytes: number; heapUsedBytes: number };
  components: {
    db: DiagnosticsComponentHealth & { sizeBytes: number };
    logs: DiagnosticsComponentHealth & { fileCount: number };
    backups: DiagnosticsComponentHealth & { count: number; latest: DiagnosticsBackupDTO | null };
    opencode: DiagnosticsComponentHealth;
    gateway: DiagnosticsComponentHealth;
    github: DiagnosticsComponentHealth;
    ollama: DiagnosticsComponentHealth;
  };
}
export interface DiagnosticsBackupDTO { name: string; size: number; modifiedAt: string }
export interface DiagnosticsBackupsDTO { backups: DiagnosticsBackupDTO[]; restoreNote: string }
export type DiagnosticsBackupResult = { ok: true; name: string; size: number } | { ok: false; reason: string };
export type DiagnosticsExportResult = { ok: true; path: string } | { ok: false; reason: string };
```

| Route | Direction | Payload | Result | Errors |
|---|---|---|---|---|
| `GET /diagnostics/logs` | read | — | `DiagnosticsLogListDTO` | — |
| `GET /diagnostics/logs/:file?tailBytes=` | read | `file`, `tailBytes` | `DiagnosticsLogContentDTO` | `VALIDATION_FAILED`, `NOT_FOUND` |
| `GET /diagnostics/errors?limit=` | read | `limit` | `DiagnosticsErrorsDTO` | `VALIDATION_FAILED` |
| `GET /diagnostics/health` | read | — | `DiagnosticsHealthDTO` | — |
| `GET /diagnostics/backups` | read | — | `DiagnosticsBackupsDTO` | — |
| `POST /diagnostics/backup` | write | `{}` | `DiagnosticsBackupResult` | — |
| `GET /diagnostics/export` | read | — | existing redacted archive + DB stats | — |
| `aik:diagnostics-export` | IPC | — | `DiagnosticsExportResult` | untrusted → `{ok:false, reason:'untrusted'}` |

All orchestrator routes inherit the existing loopback Host/Origin + Bearer-token hook.
The renderer bridge rejects `/events` and `/diagnostics/export` after URL normalization
(dot-segments, percent-encoding, duplicate slashes).

## Component design

1. **`packages/contracts/src/diagnostics.ts` + index export** — constants, request
   schemas, DTOs, backup/export result unions (K-12). Add contract schema tests.
2. **`packages/contracts/src/bridge.ts` + `apps/desktop/src/preload/index.ts`** — add
   `exportDiagnostics(): Promise<DiagnosticsExportResult>` to `AikWindowApi` and wire the
   preload invoke in the same task so typecheck stays atomic.
3. **`apps/orchestrator/src/maintenance/diagnostics.ts`** — extend the service with
   `listLogs`, `readLog`, `recentErrors`, `health`, `listBackups`, `createBackup`.
   Constructor gains optional `backupsDir`, `electronVersion` (nullable) and
   `extraComponents` probe callback. Log helpers use `lstat`/`realpath`/`openSync`/
   `readSync`/`fstat`, never whole-file reads. Export uses the same bounded tail reader,
   caps the newest 20 files / 2 MiB total, and adds `db` page/size statistics. Every
   redacted payload is scanned fail-closed (`readLog` throws; `recentErrors` omits hits).
4. **`apps/orchestrator/src/api/routes/maintenance.ts`** — add the routes using `parse()`
   so invalid tails/names return the standard `VALIDATION_FAILED` envelope; unknown files
   return `NOT_FOUND`. List handlers wrap arrays into `{files}` / `{backups, restoreNote}`.
   `/maintenance/prune` and `/diagnostics/export` keep their existing handlers.
5. **`apps/orchestrator/src/app.ts`** — pass `backupsDir: paths.backups`,
   `electronVersion: opts.versions.electron`, and probes:
   - `opencode`: `resolveOpenCodeService()` configured/unavailable (no network call),
   - `gateway`: a mutable `gatewayStarted` flag set after the gateway starts,
   - `github`: a connected row in `github_connections`,
   - `ollama`: provider rows with kind `ollama`.
6. **`apps/desktop/src/main/diagnostics-export.ts`** — electron-free orchestration of
   fetch-result → default filename → save path → write, with injected deps; unit-tested
   with temp files. Failure reasons are fixed codes, never raw errors or paths.
7. **`apps/desktop/src/main/bridge.ts`** — thin `aik:diagnostics-export` handler using a
   **non-throwing** trusted-sender check, the supervisor port/token, a native Save dialog
   and the helper above; returns a union and never throws. `bridge-request.ts` gains a
   pure `isRendererPathAllowed` normalization helper; `aik:request` returns the standard
   400 envelope for denied paths.
8. **`apps/ui/src/lib/theme.ts` + `use-theme.ts`** — preference parsing/resolution
   (pure) and one DOM store with `matchMedia` change handling, `setThemePreference`,
   `toggleTheme`, `initTheme`, `useTheme`. Snapshot is cached and replaced only on
   change. Backward-compatible `loadTheme`/`applyTheme` helpers remain.
9. **`apps/ui/src/lib/shortcuts.ts` + `use-global-shortcuts.ts` + `shortcut-help.ts` +
   `components/shell/shortcuts-dialog.tsx`** — registry (global/code/local), matcher,
   formatter, editability helper, platform detection, one stable global listener,
   custom-event opener, accessible dialog with a Close button and `max-h-[80vh]`
   scrolling.
10. **`apps/ui/src/routes/root.tsx` / `components/shell/sidebar.tsx` / `router.tsx`** —
    mount the listener/dialog, listen for the help event, add "Keyboard shortcuts" and
    "Diagnostics" entries, add the `/diagnostics` lazy route. Settings appearance card
    exposes Light/Dark/System radios (with System described), a quick toggle label based
    on the **resolved** theme, and a "Keyboard shortcuts" button. CodePage switches to
    `matchesShortcut` from the registry (same chords as today).
11. **`apps/ui/src/lib/diagnostics.ts` + `routes/diagnostics.tsx`** — pure formatting
    helpers and the page: health cards for all seven components, recent errors, log
    selector/viewer with truncation display and an unchecked auto-refresh (pauses while
    focused/selected), backup button/list + prune/restore copy, export button, accessible
    live status, loading/empty/error/stale states.

## Security and privacy

- Log content is redacted at the service boundary, never in the renderer. The redactor
  holds the launch, gateway and office tokens; patterns now also cover JWTs,
  `x-api-key`/cookies, database URL userinfo (postgres/mysql/redis/mongo/amqp), npm,
  GitLab and Hugging Face tokens. The archive export keeps its final secret scan.
- Log reads are allow-listed by name and directory, reject symlinks/junctions, confirm
  regular files after open, and never read more than the requested tail. Export/recent
  errors cap file count and total bytes. `orchestrator-stdio.log` remains append-only on
  disk (pre-existing; the export path is now memory-bounded).
- `/diagnostics/*` sits behind the existing auth/host/origin hook. `/diagnostics/export`
  is removed from the renderer bridge allow-list after URL normalization, alongside a
  hardened `/events` denial.
- The export handler checks the IPC sender without throwing, uses the token only in
  main, writes only to the path the user picks in the native dialog, and returns a union.
- Backups are database snapshots inside the app data directory; the endpoint is
  authenticated, single-flight, throttled and pruned. Restoring a live DB is not exposed.
- No agent gains access: shortcuts/theme are renderer-only, diagnostics is user-only API
  surface, and OpenCode permissions/config are untouched.

## Accessibility

- The shortcut dialog uses the existing Radix `Dialog` (focus trap, Escape, title,
  focus restore), a Close button, bounded height/scroll and real `<kbd>` text. Overlay
  surfaces use the new theme tokens so light-theme contrast is AA.
- Theme choices are a labelled radio group with visible focus rings and a description
  for System; the quick toggle is a normal button labelled from the resolved theme.
- Health/errors/log/backup actions are buttons/selects with labels; async results use
  one persistent page-level `role="status" aria-live="polite"` region, errors use
  `role="alert"`. The log `<pre>` is focusable/scrollable and never a live region.
- Health badges carry text status, not colour alone. Light `--muted-2` is darkened to
  meet 4.5:1 for small metadata.

## Testing and verification

- Contracts: schema boundary tests (tail min/max/coercion, log-name regex accepts
  `orchestrator.log.3`, rejects traversal/absolute/`.db`).
- Orchestrator service: list/read tails across rotation, UTF-8 boundary behaviour,
  truncation flag, unknown file → null, symlink escape rejected, redaction of a token
  placed in a log line, fail-closed scan, error extraction levels/sorting/limit,
  health shape with all components, DB size, backup create + prune + throttle +
  single-flight, backup failure reason.
- Orchestrator routes: authenticated 200s, 400 for bad tail/limit/name, 404 for an
  unknown-but-valid name, `/health` unchanged, backup round-trip, export shape.
- Desktop: export helper success/cancel/fetch-failure/write-failure/filename;
  `isRendererPathAllowed` rejects `/events`, `/x/../events`, `/%65vents`,
  `/diagnostics/export` and allows normal paths.
- UI pure: theme parse/resolve/default/system, shortcut match/format/editability,
  diagnostics format bytes/age.
- E2E: global nav/F1/theme toggle + system follow; Diagnostics page loads health/logs,
  shows a known log line, creates a backup; direct API returns a redacted line for a
  seeded AWS-key-shaped secret and 400/404 for bad log names; modal/editability
  suppression is unit-tested.
- Final gate: `npm run check:pins && npm run lint && npm run typecheck && npm test`,
  then `npm run build && npm run e2e`.

## Parent-spec amendments (recorded; apply to the parent file in the docs task)

1. **§17.3 `GET /diagnostics/export`** says "ZIP of redacted logs and DB statistics".
   REL-7 shipped a redacted **JSON** archive (the endpoint, tests and desktop export all
   consume JSON). This phase keeps JSON and adds DB statistics; the parent wording is
   amended to "redacted JSON archive of logs, DB statistics and platform metadata
   (no DB file, no secrets)".
2. **§6.10 / §23 screen 21 restore** says "Restore a backup from the diagnostics
   screen". Restoring a live database from the running app is a data-loss risk and needs
   a supervisor stop/restore/restart protocol not present in this phase. The parent is
   amended to "Restore is offered from the startup failure screen when the database
   cannot open; the diagnostics screen lists backups and explains the restore path."
   This keeps the existing guarded `restoreLatestBackup` as the only restore path.
3. **§23 screen 20** lists retention and notifications in Application settings. This
   phase does not add those settings; REL-7's retention job remains server-side and
   notification settings remain future work. Recorded as an explicit deferral, not a
   claim of screen-20 completion.

## Deferred / follow-ups

- User-rebindable shortcuts with conflict detection and reset.
- Live log streaming/SSE and log-level filtering.
- General live-DB restore (needs a supervisor stop/restore/restart protocol and UX

- Retention interval configuration and notification settings in the UI.
- Log file download (separate from diagnostics export).
- Rotating `orchestrator-stdio.log` in desktop main (pre-existing unbounded append;
